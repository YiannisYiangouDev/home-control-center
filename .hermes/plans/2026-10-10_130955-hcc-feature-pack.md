# hcc Feature Pack — Implementation Plan (updated)

> Status log (see Progress table below). Deliverables that shipped are marked ✅; remaining ⬜.
> Repo `main` deployed on Unraid `/mnt/user/appdata/home-control-center`, `docker-compose up -d --build app`.

**Goal:** Turn home-control-center from a static dashboard into an editable, monitoring-capable, extensible control center — (1) editable home layout, (2) more widgets, (3) real monitoring, (4) advanced mode, (5) Uptime Kuma integration.

**Architecture:** Reuse the Next.js 15 App Router + server-actions architecture. Layout lives in the existing `settings` key/value table. Widgets are a named registry (`src/components/dashboard/widgets/registry.ts`) so edit mode and new widgets share one mechanism. Monitoring needed **no schema change** (`services`, `metrics`, `alerts` already existed) — it only needed data + a HEAD/GET tolerance fix.

**Tech Stack:** Next.js 15.5.23 (App Router, `output: "standalone"`), NextAuth v5 beta (JWT), Prisma + MySQL 8, Tailwind v4, framer-motion, recharts, Zod, TanStack Query.

## Phase 3 — "monitor" (kuma-like, built in)

- ✅ **3.1** Seeded 8 services (idempotent SQL; schema has no unique on `name`, so guarded by `WHERE @cnt = 0`): HA :8123, NPM :81, Unraid :/, Gotify :8070, Hellenic Conference, GiftWise `/login`, Greek Music www, Internet (one.one.one.one). All `type='CUSTOM'` (ServiceType enum is only DOCKER/WEB/API/DATABASE/CUSTOM). All `expectedStatus=200`.
- ✅ **3.2** SSRF guard: `.env ALLOWED_INTERNAL_HOSTS=192.168.0.200` already set; public targets pass normally. `safe-fetch.ts` `redirect:"manual"` → chose URLs that return 200 without redirects (GiftWise `/login`, Greek Music `www`, one.one.one.one).
- ✅ **3.3** Per-check `Metric` rows already recorded by `checkService` (`prisma.metric.create`). Verified 44 rows/min.
- ✅ **3.4** Status transitions → alerts: existing logic already creates CRITICAL alert on OFFLINE (dedup 1h) + resolves on recovery + latency alerts, and fires `sendAlertNotification` (Discord/Telegram/Gotify). **Key fix added:** the checker only sent `HEAD`, which HA rejects (405) and Gotify (404). Added GET fallback in `src/actions/services.ts` on HEAD 404/405/501. Without it HA/Gotify could never read ONLINE.
- ✅ **3.5** Wire polling — `POLLING_INTERVAL=60` env controls the worker (`sleep $POLLING_INTERVAL`). The dead `POLLING_INTERVALS` constant (`src/lib/constants.ts:77`) is still unused; dashboard server revalidates every 10 s (`export const revalidate = 10`). ⬜ Optional: wire UI auto-refresh via React Query `refetchInterval` or lower `revalidate`.

**Open risks**
- Alert-flapping: current code alerts on single OFFLINE, dedups only 1h. Consider N-consecutive-failure before OFFLINE (use `Metric` history) if flapping becomes noisy.
- `MIN_ALLOWED_INTERNAL` / any new LAN target must be added to `ALLOWED_INTERNAL_HOSTS` or the check reports DEGRADED (responds but blocked → actually blocked throws → OFFLINE). Add hosts when adding services.

## Deploy loop (proven)

```bash
cd /workspace/home-control-center && npm run build          # must exit 0 (Next type-checks)
git add -A && git commit -m "…" && git push origin main
# propagate changed files to Unraid appdir (NOT a git checkout):
scp -i /opt/data/.ssh/id_ed25519 src/... root@192.168.0.200:/mnt/user/appdata/home-control-center/src/...
# new dirs: scp -r first (e.g. widgets/)
ssh root@192.168.0.200 'cd /mnt/user/appdata/home-control-center && /usr/local/bin/docker-compose up -d --build app'
ssh root@192.168.0.200 'curl -s http://127.0.0.1:3030/api/health'
```
SSH via alias `unraid` (config `/opt/data/.ssh/config`, key `/opt/data/home/.ssh/id_ed25519`) is preferred to avoid raw-IP approval noise. Container lifecycle via ssh → `/usr/local/bin/docker-compose` (no compose plugin).

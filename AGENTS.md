# Home Control Center

Self-hosted home-server command center (PWA dashboard). Next.js 15 App Router (`output: "standalone"`, Turbopack dev), NextAuth v5 beta (credentials provider + JWT sessions), Prisma + MySQL 8, Tailwind v4, Zod, React Query, recharts. Monitors Unraid / Nextcloud / Home Assistant, services, and alerts; ADMIN/VIEWER roles; optional TOTP 2FA. Deployed as a Docker Compose stack (app + mysql + worker + prometheus).

## Dev environment

- Node >= 22 (`engines` in package.json). No local dev DB — run MySQL via Docker: `docker compose up -d mysql`.
- `cp .env.example .env`, then generate real secrets: `openssl rand -base64 32` for `AUTH_SECRET`, `WORKER_API_SECRET`, MySQL passwords; `openssl rand -hex 32` for `ENCRYPTION_KEY`. Placeholder values are rejected at runtime.

## Tests

None. No `test` script, no test files, no CI (`.github` absent). Verify changes with `npm run build` plus manual checks. Healthcheck endpoint: `/api/health`.

## Conventions (observed)

- Path alias `@/*` → `./src/*`.
- `src/actions/*.ts` are server actions (`"use server"`). Each returns `ActionResult` (`{ success, error?, message? }` from `@/types`), opens with `const session = await auth()`, and gates ADMIN-only mutations on `(session.user as { role: string }).role !== "ADMIN"`.
- Input validation: Zod schemas in `src/lib/validators.ts`; actions call `schema.safeParse(...)`; types derived via `z.infer<typeof schema>`.
- DB access only through the singleton `src/lib/prisma.ts` (globalThis cache in dev).
- Server credentials encrypted at rest with `encryptCredentials`/`decryptCredentials` from `src/lib/crypto.ts` (AES-256-GCM, `iv:authTag:ciphertext` hex). Never store raw credentials.
- Mutations write an `AuditLog` row (`prisma.auditLog.create`, action like `CREATE_SERVER`).
- External API clients live in `src/services/<name>/client.ts`; client components co-located under `src/components/<feature>/`.

## Pitfalls

- Boot-time secret validation (`src/lib/env-validate.ts`) throws unless `AUTH_SECRET`, `WORKER_API_SECRET`, `ENCRYPTION_KEY` are each >= 32 chars and contain no weak substring. Skipped only during `next build` (`NEXT_PHASE === "phase-production-build"`), so `npm start` can fail after a successful build. `ENCRYPTION_KEY` must additionally be exactly 64 hex chars.
- `BYPASS_AUTH=true` is a hard startup failure in production (`assertNoBypassAuth`).
- Fresh DB is created automatically by the entrypoint (`prisma migrate deploy` — one squashed migration holds the full 12-table schema). The only manual step is seeding admin; the seed exits if `ADMIN_PASSWORD` is unset or < 12 chars.
- The rate limiter (`src/lib/rate-limit.ts`) is an in-memory `Map` — resets on restart, not shared across app replicas.
- `getClientIp` trusts the LAST `x-forwarded-for` entry; only correct behind a reverse proxy that sets/overrides that header.
- PWA artifacts (`public/sw.js`, `public/swe-worker-*.js`, `public/workbox-*.js`) are gitignored and regenerated by next-pwa on every build — don't hand-edit or commit them.
- Ports: app `3030` (host) → `3000` (container); Prometheus UI bound to `127.0.0.1:9090` only; MySQL is `expose`-d internally, not published to the host.
- Worker polls `/api/cron/poll-services` with a `WORKER_API_SECRET` bearer token; `ALLOWED_INTERNAL_HOSTS` gates which LAN hosts the polling code may reach (SSRF guard).
